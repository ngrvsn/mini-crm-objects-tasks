# Решения и допущения

- «Удалить» означает скрыть объект или задачу. Записи истории остаются в БД и не редактируются через API.
- «Принята» — конечный статус. Постановщик может менять название, описание, объект и исполнителя задачи без подмены прежней истории статусов.
- Исполнитель видит только свои активные задачи и объекты, где такие задачи есть. Имена и роли пользователей видны вошедшим сотрудникам для назначения и отображения автора; email через таблицу профилей не раскрывается.
- Статус задачи меняется только отдельной функцией БД. При возврате на доработку комментарий обязателен. Начальное событие «Создание → Новая» тоже входит в историю.
- Парольный вход и обновление сессии обрабатывают Next.js Route Handlers. Axios обращается к Data API с publishable key и access token; секретный ключ в приложении не нужен.
- Проверки CI используют отдельную локальную Supabase, а не рабочую базу. На рабочем проекте применяются только миграции без сброса данных.
- В ТЗ указан объём 2–3 часа, но по запросу заказчика добавлены тесты, проверки безопасности и CI, поэтому фактический объём больше.
- CRM размещена на предоставленном сервере отдельным контейнером по пути `/crm` существующего HTTPS сайта. Это позволяет удалить тестовый стенд одним скриптом без изменений Minecraft. Облачные тестовые пользователи созданы через Auth Admin API с отдельным секретным ключом; он не используется приложением и не входит в репозиторий. Демонстрационные объекты и задачи созданы под учётными записями постановщика и исполнителей через обычный Data API.
